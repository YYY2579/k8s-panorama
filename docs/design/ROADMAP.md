## 1. 现状定位（先想清楚它是什么）

全景架构图**不是集群的镜像**，而是**排障时的导航图**。这个定位决定了一切后续设计：

| | 全景架构图（现有） | 集群视图（待建） |
|---|---|---|
| 数据来源 | 人工维护的知识数据（SQLite） | 真实 K8s API 的只读快照 |
| 变化速度 | 慢变量，随版本发布 | 快变量，秒级 |
| 节点含义 | 概念全集：K8s 世界里**有**这个组件 | 实例实存：你的集群里**装了**这个组件 |
| 失效模式 | 永不失效（本地库） | 集群不可达时失效 |
| 布局 | 手写坐标，表达逻辑层次 | 按实际拓扑与状态 |

**核心心智模型：全景图是"概念全集"，集群层只做"状态标注"，不做"删改"。**
集群里没有 Gateway API，不代表这个概念不存在 —— 只在全景图上标注「集群中未检测到」。
这条是整个方案不冲突的根基。

## 3. 开发顺序与里程碑

### 3.1 总顺序

```
M1 可信（纯增量，不动现有代码）
  ├─ 1a 鉴权与权限
  ├─ 1b CI + pytest
  └─ 1c Alembic 迁移
        ↓
M2 连得上（新增独立模块，现有代码零改动）
  ├─ 2a 集群只读探针：/api/cluster/* + 降级 + TTL 缓存
  └─ 2b 资源可视化展示：槽位填充 + 状态连线 + 右栏命令面板
        ↓
M3 排得断（最初的核心诉求）
  ├─ 3a 故障剧本 + 交互式 SOP 判分
  └─ 3b 排查进度记录与复盘
        ↓
M4 用得久
  ├─ 第二阶梯剩余项（可观测性 / 前端 TS / 软删除 / 自动布局 / 全文检索）
  └─ 第三阶梯（主题 / 导出 / i18n / 快捷键 / 分页 / lint / LICENSE）
```

M1 优先是因为它**纯增量、零风险、当天见效**（GitHub 绿勾），先把项目可信度立住；
M2 是差异化核心，且按铁律设计成对现有代码零侵入；M3 呼应项目最初的排障诉求。

### 3.2 里程碑出口标准

| 里程碑 | 内容 | 出口标准 |
|---|---|---|
| **M1a 可信** | 鉴权 | 未登录 401；viewer 不可写；写操作记录操作者 |
| **M1b 绿勾** | CI + pytest | Actions 跑 `pytest` + `test_api.py` 全绿；README 有 badge；`pytest` ≥ 40 用例 |
| **M1c 可迁** | Alembic | `alembic upgrade head` 可从空库建到当前结构；`reset_db.py` 退位为开发工具 |

## 4. 明确不做的事（范围边界）

1. **永不实现集群写操作**。不是"暂不开放"，是代码里不存在写方法。
2. **v1 只支持单集群**。多集群留给 v2，避免选择器、上下文切换、权限矩阵一起爆炸。
3. **不改全景图的手写坐标**。那是它的表达方式，自动布局只作用于集群视图。
4. **不引入 Helm / Operator**。部署保持"宿主机 + Docker Compose"两套就够。
5. **不为接入集群而改现有 `/api/atlas/*` 的任何契约**。见下节冲突规避。

---

## 5. 冲突规避总原则

详见 [`k8s-cluster-module.md`](k8s-cluster-module.md)，六条铁律摘要：

1. **路由隔离** —— `/api/cluster/*` 与 `/api/atlas/*` 物理分离，互不 import
2. **数据不混表** —— 集群状态只进独立缓存/快照表，绝不写 `node` / `edge`
3. **布局共享、数据分离** —— 集群视图复用全景图的固定槽位坐标（布局是心智锚点），
   但数据源独立；被否决的是"同一张图叠加两层数据"的 overlay 方案
4. **只读边界** —— 客户端白名单化，只有 GET，写方法不存在
5. **故障不传染** —— 集群不可达 → 降级为纯知识图谱，其他功能零影响
6. **凭证隔离** —— kubeconfig / ServiceAccount 配置独立，只被集群模块读取

## 6. 待决策项

| 问题 | 选项 | 建议 |
|---|---|---|
| 鉴权方案 | session-cookie / JWT / Basic Auth | session-cookie + `itsdangerous`，最简单且够用 |
| 集群凭证来源 | kubeconfig 文件 / ServiceAccount token / 二者皆可 | 先做 kubeconfig 文件，SA token 作为第二来源 |
| 集群视图形态 | 独立页签 / 全景图叠加层 | **独立页签**（叠加层就是冲突源本身） |
| 集群视图布局 | 复用全景图槽位坐标 / 按实际拓扑重新推导 | **复用槽位坐标**（布局是心智锚点，坐标是布局不是数据） |
| 是否需要快照落库 | 纯内存 TTL / 落 `cluster_snapshot` 表 | 纯内存 TTL 起步，需要历史对比时再落库 |
| 排障演练的判分方式 | 步骤顺序严格匹配 / 关键步骤匹配 | 关键步骤匹配，容错但仍有约束 |
