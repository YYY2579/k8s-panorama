# 手工验收步骤

前置：后端已启动（`cd backend && python run.py`），浏览器打开 <http://127.0.0.1:8000/>。

每一步都给出**三个可验证点**：点什么 → 界面上应该看到什么 → 数据库里应该多出什么。
第三点可以用 `curl http://127.0.0.1:8000/api/audit?limit=3` 或刷新页面看「最近变更」表格确认。

---

## 1. 首屏数据来自后端（不是写死的）

| 操作 | 界面表现 | 反证方式 |
|---|---|---|
| 打开首页 | 状态栏显示「已加载 41 个组件 / 42 条关系」 | 把 `backend/data/atlas.db` 改名后重启服务，页面会变成 0 组件 —— 证明数据来自库，不是写死 |

---

## 2. 新建一个组件（Create）

| 操作 | 界面表现 | 数据库变化 |
|---|---|---|
| 点顶栏「+ 新建组件」 | 弹出表单 | — |
| ID 填 `my-test`，名称填 `我的测试组件`，分组选任意，分类选「策略」，坐标 X=1200 / Y=560 | — | — |
| 点「创建」 | 提示「已创建组件：我的测试组件」；画布上多出一个卡片（在 ③ 集群网络模型 分组右侧） | `node` 表多一行；`audit_log` 多一条 `create / node / my-test` |

**验证**：
```bash
curl http://127.0.0.1:8000/api/nodes/my-test
```

## 6. 知识条目 + 状态流转（核心）

| 操作 | 界面表现 | 数据库变化 |
|---|---|---|
| 点页签「知识库」 | 列出 3 条种子条目 | — |
| 点「+ 新建条目」，slug 填 `manual-note`，标题填 `手工测试条目`，正文随便写 | — | — |
| 点「创建」 | 列表顶部出现该条目，状态标签为灰色 `draft` | `note` 表多一行，`status='draft'` |
| 点该条目的「提交评审」 | 状态标签变黄 `review` | `note.status` 变 `review`；审计多一条 `transition / note` |
| 点「发布」 | 状态标签变绿 `published` | `note.status` 变 `published` |
| 点「归档」→「恢复」 | 状态先变灰 `archived`，再回到 `draft` | 两次状态变更都有审计 |

**非法流转验证**：
```bash
# 把 manual-note 先弄成 published，再试图 publish，应返回 400
curl -X POST http://127.0.0.1:8000/api/notes/manual-note/transition \
  -H "Content-Type: application/json" -d '{"action":"publish"}'
```

| 操作 | 界面表现 | 数据库变化 |

| 命令行导入回灌 | — | — |

```bash
curl -s http://127.0.0.1:8000/api/io/export -o export.json
curl -X POST "http://127.0.0.1:8000/api/io/import?mode=merge" \
```

---

## 14. 重启后数据不丢（持久化验证，最关键）

1. 按第 2 步新建一个组件 `persist-check`
2. **Ctrl+C 停掉后端，再重新 `python run.py`**
3. 刷新浏览器 → `persist-check` 仍在画布上
4. `curl http://127.0.0.1:8000/api/nodes/persist-check` → 仍返回 200

> 能通过这一条，说明数据确实落在 `backend/data/atlas.db`，而不是页面内存。
